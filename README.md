# برین‌زر | فروشگاه لاراول

ویترین فارسی راست‌به‌چپ و پنل مدیریت گالری طلای ۱۸ عیار در بازار تهران. Laravel 12، Blade، CSS و جاوااسکریپت ساده. ساخت فرانت‌اند یا نصب Node برای اجرای این سورس لازم نیست.

## اجرا در محیط توسعه

نیازمندی‌ها شامل PHP 8.2+ با افزونه‌های لاراول، PDO SQLite و Composer است.

```sh
composer install
cp .env.example .env
touch database/database.sqlite
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
```

در `.env` مقادیر `APP_URL`، `APP_NAME` و `BARIN_ADMIN_EMAIL` را تنظیم کنید. نمونه‌ها را با `--seed` اضافه کنید. حساب مدیر با فرمان زیر ساخته می‌شود و رمز به‌شکل تعاملی دریافت می‌شود.

```sh
php artisan barin:admin manager@example.com
php artisan serve
```

ویترین در `/`، پنل در `/admin`. برای تنظیمات عمومی، پایگاه داده و فضای بارگذاری را پشتیبان‌گیری کنید. روی سرور، ریشه وب را روی `public/` بگذارید، HTTPS و `APP_DEBUG=false` را فعال کنید و از اجرای scheduler اطمینان بگیرید.

## پنل مدیریت

- **صفحه‌ساز** عنوان، متن، تصویر، دکمه، ترتیب بخش‌ها، پیشنهاد بودجه و بخش راهنما را از رکورد `home` تنظیم می‌کند. `catalog` برای عنوان و متن ویترین و `guide` برای راهنما است. صفحات جدید در `/page/{slug}` باز می‌شوند. چیدمان Blade دارای بخش‌های از پیش تعریف‌شده است.
- **محصول** شامل وزن به میلی‌گرم، اجرت، سود، تخفیف، مالیات، موجودی، بهای تمام‌شده و گالری مرتب است. نخستین تصویر بندانگشتی محصول است. ابتدا عکس‌های اصلی یا زاویه‌ها را در استودیو بارگذاری کنید و سپس مسیرهای دریافتی را سطر به سطر در محصول وارد کنید.
- **کمپین** بنر زمان‌بندی‌شده، جایگاه خانه/محصول، محصول هدف و قالب مناسبتی دارد. مقدار ۷۰۰ در فیلدهای درصد برابر ۷٪ است. اگر چند تخفیف برقرار باشد، بیشترین تخفیف معتبر اعمال می‌شود. قیمت طلا و اجرت، مبنای سود تنظیم‌شده‌اند و در مدل نمونه تخفیف از اجرت و سود کم می‌شود. قواعد مالیاتی پیش از فروش واقعی باید طبق رویه فروشگاه تنظیم شوند.
- **سئو** ویرایش متا، Canonical، Noindex، پیش‌نمایش نتیجه جستجو و کنترل طول عنوان، توضیح و کلیدواژه را ارائه می‌کند. صفحه محصول داده ساختاریافته دارد و sitemap و robots خودکارند. بهینه‌سازی رتبه و تحلیل جامع محتوای Yoast در این نسخه ارائه نشده است.
- **مالی** ریز قیمت قفل‌شده برای سفارش، گزارش پرداخت‌های تأییدشده، تخفیف، حاشیه ناخالص بر پایه بهای ثبت‌شده و خروجی CSV را دارد. سفارش در وضعیت انتظار تأیید، موجودی را رزرو می‌کند و لغو سفارش پرداخت‌نشده موجودی را آزاد می‌کند. جریان فعلی ثبت سفارش و تأیید دستی پرداخت است. درگاه، برگشت وجه، ارسال خودکار و اتصال حسابداری به انتخاب سرویس و توسعه تکمیلی نیاز دارند.

## نرخ بازار

میزبان معتبر سرویس را به `BARIN_INTEGRATION_HOSTS` در `.env` اضافه کنید. نشانی HTTPS، واحد ریال/تومان، مسیر مقدار در JSON مثل `data.price` و توکن Bearer را در بخش تنظیمات وارد کنید. پاسخ باید نرخ **هر گرم طلای ۱۸ عیار** باشد. با «دریافت نرخ از API» تست کنید. برای دریافت خودکار هر دقیقه، scheduler لاراول را اجرا کنید.

```sh
* * * * * cd /var/www/barin-zar && php artisan schedule:run
```

نوار ویترین هر دقیقه آخرین نرخ ثبت‌شده و زمان شمسی دریافت آن را از خود فروشگاه می‌خواند. هنگام تغییر مبلغ نرخ، لینک دریافت قیمت‌های به‌روز محصولات در همان نوار نمایش داده می‌شود. سفارش با نرخ API قدیمی‌تر از ۲۰ دقیقه یا نرخ نمونه در محیط production ثبت نمی‌شود. زمان سرور و پاسخ سرویس را هنگام استقرار کنترل کنید. توکن‌ها با کلید برنامه رمز می‌شوند.

## استودیو

مسیر HTTPS سازگار با قرارداد OpenAI Images Edits، نام مدل و توکن را در تنظیمات ثبت کنید. این اتصال درخواست multipart با image، prompt، model و size می‌فرستد و انتظار دارد تصویر در `data.0.b64_json` برگردد. بسته شامل ۳۲ پرامپت برای محصول، تامنیل، عکس روی مدل و نمای جزئیات است. تصویر تولیدشده ابتدا در فضای خصوصی مدیر می‌ماند. برای انتشار پس از بررسی، خروجی را دانلود و از فرم بارگذاری عمومی وارد گالری کنید. عکس روی مدل تصویر تبلیغاتی است. برای نمایش زاویه و جزئیات فنی قطعه از عکس واقعی همان زاویه استفاده کنید.

## توسعه افزونه

در `config/barin.php` فهرست `plugins`، کلاس‌های Service Provider های مورد اعتماد را می‌پذیرد. افزونه می‌تواند سرویس‌ها و مسیرهای خودش را از یک پکیج Composer یا فایل‌های پروژه ثبت کند. نصب کد از داخل پنل پیاده نشده است.

این سورس باید روی میزبان PHP اجرا شود. پیش‌نمایش Sites دارای بوتیک نمایشی مستقل و قیمت‌های نمونه است.

## Docker و استقرار روی دارکوب

### تست محلی با Compose

`.env.docker.example` را به `.env.docker` کپی کنید. برای `APP_KEY` مقدار
`base64:` به‌همراه خروجی `openssl rand -base64 32` قرار دهید. مقادیر
`MYSQL_PASSWORD` و `DB_PASSWORD` یکسان باشند و برای `MYSQL_ROOT_PASSWORD`
رمز مستقل بگذارید.

```sh
docker compose up -d --build mysql web
docker compose exec --user www-data web php artisan barin:admin manager@example.com
docker compose up -d scheduler
```

ویترین محلی در `http://localhost:8080` در دسترس است. مقدار `BARIN_DB_SETUP=demo` در نمونه تنظیمات، جدول‌ها و کاتالوگ نمایشی را هنگام راه‌اندازی وب آماده می‌کند. فایل `.env.docker` روی میزبان، داده‌های MySQL در volume به نام `mysql` و بارگذاری‌ها در volume به نام `media` ذخیره می‌شوند. هنگام به‌روزرسانی، همین فایل و volumeها را استفاده کنید. پس از تغییر `.env.docker`، سرویس‌های وب و scheduler را با `docker compose up -d` دوباره ایجاد کنید. تغییر رمز در فایل، رمز کاربر یک دیتابیس MySQL از قبل ساخته‌شده را عوض نمی‌کند.

### دارکوب

- ریشه مخزن را برای Build انتخاب کنید. پورت کانتینر وب `80` و مسیر بررسی سلامت `/up` است. پوشه `public/` ریشه Apache است.
- یک سرویس MySQL جداگانه یا مدیریت‌شده به اپ متصل کنید. اگر MySQL را خودتان در کانتینر اجرا می‌کنید، دیسک داده را در همان سرویس روی `/var/lib/mysql` سوار کنید. برای فروشگاه موجود، نشانی همان دیتابیس را وارد کنید.
- برای فایل تنظیمات، یک پارتیشن روی `/run/barinzar-config` سوار کنید و فایل `.env` را داخل آن بگذارید. اسکریپت شروع با دسترسی root از آن یک کپی خصوصی با مجوز `0640` و گروه `www-data` در مسیر `.env` برنامه می‌سازد؛ مجوز و مالک فایل اصلی یا پارتیشن را تغییر نمی‌دهد. فایل اصلی می‌تواند فقط برای root قابل خواندن یا روی پارتیشن فقط‌خواندنی باشد. تنظیمات را در فایل اصلی ویرایش کنید و اپ را ری‌استارت کنید تا کپی به‌روزرسانی شود. متغیرهای واقعی محیط اجرا بر مقادیر فایل اولویت دارند. می‌توانید به‌جای فایل، تمام تنظیمات را در متغیرهای محیط اجرای اپ ثبت کنید.
- برای بارگذاری‌ها، پارتیشن جداگانه‌ای روی `/var/www/html/storage/app` سوار کنید. پیوند `public/storage` بخشی از ایمیج است.
- راه‌اندازی خودکار دیتابیس با دستور پیش‌فرض ایمیج `apache2-foreground` اجرا می‌شود. برای راه‌اندازی خودکار روی دارکوب، در شروع از یک replica وب استفاده کنید. حالت `demo` در کاتالوگ خالی ۱۰۰ محصول، صفحه اصلی، راهنمای خرید و نرخ نمونه را یک‌بار اضافه می‌کند. نرخ نمونه برای ثبت سفارش در محیط production معتبر نیست. حالت `migrate` فقط migrationها را اجرا می‌کند. حالت `off` پیش‌فرض است و برای اجرای جداگانه `php artisan migrate --force` کاربرد دارد.
- حساب مدیر را یک‌بار با `php artisan barin:admin manager@example.com` بسازید و همان ایمیل را در `BARIN_ADMIN_EMAIL` بگذارید.
- برای نرخ خودکار، یک پردازش جدا با همان ایمیج، همان متغیرهای پایگاه داده و کلید، و دستور `php artisan schedule:work --no-interaction` بسازید. Scheduler فقط یک replica داشته باشد و برای نرخ‌گیری به دیسک تصاویر نیاز ندارد.
- دامنه را روی وب‌اپ متصل کنید. برای قرار گرفتن پشت پراکسی HTTPS، در صورت نیاز `APP_TRUSTED_PROXIES` را با IP یا CIDR پراکسی‌های مورد اعتماد تنظیم کنید.

نمونه `/run/barinzar-config/.env` روی دارکوب

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://your-domain.example
APP_KEY=base64:replace-with-your-existing-key
LOG_CHANNEL=stderr
DB_CONNECTION=mysql
DB_HOST=your-internal-mysql-host
DB_PORT=3306
DB_DATABASE=barinzar
DB_USERNAME=barinzar
DB_PASSWORD="replace-with-your-database-password"
BARIN_ADMIN_EMAIL=manager@example.com
BARIN_DB_SETUP=demo
```

اگر قبلاً کلید را در `/run/barinzar-config/app_key` نگه داشته‌اید، همان مقدار را در `APP_KEY` فایل جدید بگذارید. با فایل پایدار و دستور پیش‌فرض ایمیج، می‌توانید دستور اجرایی سفارشی قبلی را از پنل حذف کنید. برای bootstrap دستی همان داده نمایشی پس از migration، از `php artisan db:seed --class=DemoInstallationSeeder --force` استفاده کنید.

### اجرای موقت با SQLite

فایل تنظیمات پایدار را با این مقادیر هماهنگ کنید و `APP_KEY` قبلی را حفظ کنید:

```dotenv
DB_CONNECTION=sqlite
DB_DATABASE=/var/www/html/storage/app/private/database.sqlite
SESSION_CONNECTION=sqlite
BARIN_DB_SETUP=demo
```

پارتیشن `/var/www/html/storage/app` باید پایدار باشد. در حالت `demo` یا `migrate`، پردازش وب فایل SQLite گمشده را با کاربر `www-data` می‌سازد و سپس migrationها را اجرا می‌کند. فایل موجود بازنویسی نمی‌شود. حالت `off` و پردازش scheduler فایل دیتابیس نمی‌سازند. برای SQLite از یک replica وب استفاده کنید. حالت `demo` همان کاتالوگ نمونه را طبق قواعد راه‌اندازی قبلی اضافه می‌کند.

### افزایش محصولات نمونه در نصب موجود

برای تکمیل کاتالوگ قبلی به ۱۰۰ محصول نمایشی، پس از دریافت نسخه جدید اجرا کنید:

```sh
php artisan db:seed --class=DatabaseSeeder --force
```

اجرای دوباره محصول تکراری ایجاد نمی‌کند و داده‌های محصولات موجود را بازنویسی نمی‌کند. محصولات دستی نیز حفظ می‌شوند، بنابراین با وجود محصولات دستی ممکن است تعداد کل از ۱۰۰ بیشتر شود. راه‌اندازی خودکار `DemoInstallationSeeder` فقط برای نصب اولیه است؛ ری‌استارت به‌تنهایی کاتالوگ قبلی را تکمیل نمی‌کند. محصولات جدید از تصاویر نمونهٔ همراه پروژه استفاده می‌کنند.
